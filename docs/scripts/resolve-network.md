# resolve-network.ps1

## Purpose

Resolves network controller capability profiles from the live hardware inventory without modifying the OpenCore configuration.

The stage is hardware-agnostic. Hardware-specific knowledge lives in `config/hardware/network/*.json`; the PowerShell implementation does not contain controller-specific branches.

## Inputs

- `build/opencore/hardware-detected.json`, produced by `configure-opencore-hardware.ps1`.
- `config/hardware/network/**/*.json`, containing declarative network controller profiles.

Profiles may match network PnP identities using vendor, device and subsystem IDs. The current RTL8125 profile declares a profile-managed Ethernet kext strategy.

## Output

`build/opencore/network-resolution.json` contains:

- matched profile IDs;
- resolved controller strategy;
- validation requirements;
- adapters without a matching profile;
- unresolved capabilities;
- safety warnings;
- artifacts intentionally not generated by this stage.

The report is written transactionally and an existing report is backed up before replacement.

## Separation of responsibilities

This stage does **not** download or compose kexts. Kext selection, dependency resolution, asset acquisition and `Kernel -> Add` composition remain the responsibility of the dedicated kext pipeline stages.

The network resolver only establishes whether a declarative hardware capability profile applies and whether additional macOS-side validation is required.

## Safety model

Windows driver names and versions are not treated as proof of macOS driver compatibility. Therefore this stage never invents:

- network kext binaries from Windows driver versions;
- `Kernel -> Add` entries;
- device properties or GPU-style spoofing for network controllers;
- macOS network interface configuration.

When a controller profile matches but requires validation, the result is `NeedsValidation`, not failure. When no profile matches a detected controller, that adapter remains explicitly unresolved and is not guessed into another profile.

## Transaction and rollback

The stage uses the shared transaction and rollback libraries. If report generation fails, the previous report is restored, or the newly created report is removed. Successful completion commits the transaction.

## Usage

From an elevated PowerShell session:

```powershell
Set-Location <devintosh-repository>
.\scripts\resolve-network.ps1
```

## Expected state for partially supported hardware

A machine can contain several network adapters. A recognized Ethernet controller can therefore be resolved while another adapter, such as an unsupported Wi-Fi device, remains listed under `unmatchedAdapters`. This does not cause the known controller to be rejected or mapped to another profile.

No `config.plist` mutation is performed by this stage.
